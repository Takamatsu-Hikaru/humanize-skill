# humanize

[English](README_EN.md) · [中文技能](humanize/SKILL.md) · [English skill](humanize/SKILL.en.md)

**让 AI 重新说人话，写人字。**

小学弟给你扔来一份 AI 写的报告。标题是“我们接下来应该怎么做”，正文是“先建立认知，再逐步探索”，结尾是“形成完整闭环，实现全面提升”。

你读了三页，还不知道他到底做了什么。

也可能这份报告就是你让 AI 写的。你说“自然一点”，它开始“做点好玩的东西”；你说“正式一点”，它开始“赋能、抓手、闭环”；你说“直接一点”，它先花两段解释自己接下来会如何直接。

红温了。🔥

`humanize` 是一份中英文写作与编辑 skill，来自指南、赛事方案和资源页的实际修改。它让 AI 根据读者和用途重新组织表达：标题说清内容，正文提供信息，保留作者的判断，删掉多余的引导、说教和自我解释。

## 红温现场

以下对照适用于方案、报告与资源说明；右栏保留相应例子的事实和用途。

| AI 原稿 | 修改后 |
| --- | --- |
| 官网承担什么 | 官网功能 |
| 先在群里了解比赛和登记队伍 | 报名与队伍登记 |
| 群文件按这个顺序发布 | 资料发布安排 |
| 做点好玩的东西 | AI 应用体验；正文列出动作识别、开放世界探索与机械臂任务。 |
| 先让同学进得来、看得懂、能报名。 | AI 社将于 10 月 13 日发布赛事公告、三份赛题说明和队伍登记表，并建立比赛总群。 |
| 这不仅是一场比赛，更是一次探索未来、实现成长的旅程。 | 比赛设置计算机视觉、Agent 和具身智能三个方向，提供学习资料、算力支持与交流答疑。 |
| 先挑一个方向，再选一篇论文，读完后保存一次记录。 | 页面提供按研究方向筛选的论文目录，以及论文讲解与代码链接。 |
| 需要注意的是，这份指南并不能覆盖所有情况，也不能保证适合每一位读者…… | 本指南介绍 Python、模型训练与 Agent 开发的入门资料。 |

最后一例删的是泛泛的免责话。如果有具体的版本要求、失败条件或适用范围，就把它写在相关位置。

## 区别所在

**标题的作用是标明内容。** “官网功能”便于查找；“官网承担什么”在模拟问答。给同事、学长或负责人审阅的文档，通常无需把每一节都写成引导式问题。

**正文需要可供判断的信息。** 谁负责、什么时候发布、提供哪些材料，比“让大家看得懂、参与得进来”更有用。具体事实不足时，应标明缺少的内容，不能靠润色补出一套安排。

**读者有自己的理解能力。** 内容已经列清楚，就不必反复告诉人“先看这里，再做那个”。教程中的必要步骤要保留，阅读方案则不需要每段都有人带路。

**自然的文字有不同语气。** 招募文案可以活泼，审阅材料需要正式，技术文章需要准确。“像人写的”并不等于多加“试试”“做点”“一个小项目”。正式表达也可以使用普通词语。

“怎么”“先后”“一个两个”都不是禁词。“测评后十天答辩”说明时间关系，“三份赛题说明”给出准确数量。需要处理的是没有信息作用的引导和填充。

## 两遍检查

**第一遍看内容。** 整篇最终想传达什么，各 part 和每段为什么出现在这里，给前文增加了什么，怎样接到后文？主线、铺垫、例子和资源是否连贯，核心内容有没有被提醒挤掉，哪些地方值得展开，哪些只是在重复？

**第二遍看表达。** 读起来是否自然，有没有过度教学、正确但无用的话、防御性声明和自我弱化？也检查删减后是否太干，丢了经验和判断。事实、条件、引用和独有链接要保留；双语内容对齐意图和信息，不照搬句式。

检查在编辑过程中完成，不必把每次改稿都变成两轮报告。局部修改按相关上下文检查，已经成立的段落不用为了“更像人”再写一遍。

## 使用

下载 [humanize.zip](https://github.com/Takamatsu-Hikaru/humanize-skill/releases/latest/download/humanize.zip)，解压后将 `humanize` 文件夹放入你的 Agent 使用的 skills 目录，保留其中的子目录。

需要英文指令，可下载 [humanize-en.zip](https://github.com/Takamatsu-Hikaru/humanize-skill/releases/latest/download/humanize-en.zip)。两个包使用同一个技能名 `humanize`，选择一个安装即可；技能说明的语言不限制输出语言。英文包的正文、案例、配图与排版参考均为英文。

支持显式调用 skill 的工具中，可以这样请求：

```text
用 $humanize 修改这份方案。
读者是负责审阅的学长，语气正式、直接。
小标题用中性的内容名称，正文写清主体、时间和安排。
保留事实、数据，以及我已经修改过的段落。
```

也可以把 [SKILL.md](humanize/SKILL.md) 和相关参考文件提供给 AI，连同原稿一起使用。给出一段你认可的文字，通常比反复说“去 AI 味”更有帮助。

仅需改稿时直接交付改稿；需要保存文件、网页排版或公众号版本时，在请求中说明。

## 包含内容

```text
humanize/
├── SKILL.md                     写作判断与工作方式
├── SKILL.en.md                  对应英文说明
├── agents/openai.yaml           技能显示信息
├── references/
│   ├── before-after.md          指南与赛事方案的修改对照
│   ├── presentation.md          配图、页面与公众号排版
│   └── github-references.md     相关项目与参考来源
└── assets/wechat-base.css       文章排版样式起点
```

三个参考文件均有 `.en.md` 英文版；英文安装包使用英文 `SKILL.md` 和显示信息，并保留 `SKILL.zh.md` 中文说明。

纯文案使用不需要安装额外依赖。配图和排版部分按任务选用当前可用的工具。

## 案例与贡献

欢迎提交让你读得红温的句子，最好同时附上用途、读者和你认可的改法。去掉私人信息后再提交。

真正有价值的案例能说明：哪层意思被改没了，哪句话多余，为什么这个读者不需要这种引导。单列一张“AI 高频词表”，很容易把好句子一起删掉。
