# Knowledge bases: resource roles and proactive review

These cases come from an October 2026 beginner competition guide. They calibrate judgment, not a universal layout.

| Failure | Correction and check |
|---|---|
| Video covers and descriptions lack usable links | Provide a linked title or nearby text link. Link covers too when supported; they do not replace text entry points. |
| Every resource dictates “first read, then do, finally save” | Describe substance and relevant knowledge connections. Preserve real installation dependencies and requested course sequences. |
| Removing explanation leaves an unexplained image or repeated title | Add a brief substantive introduction where needed, not filler under every heading. |
| Every figure caption reports figure and PDF page numbers | Keep attribution and useful explanation. Omit production metadata unless needed for citation or navigation; page ranges distinguishing split PDFs remain useful. |
| A CUHK example is presented as a data portal without explaining its method value | Identify architecture, training, or processing value and relevant task differences. Data, methods, environments, Agent frameworks, and competition packages have different roles. |
| Official MineDojo/LIBERO practice is replaced by a competition package | Preserve the requested practice entry. Put competition procedures only in the authorized relevant section. |
| Copyable prompts blend into prose | Use a separate bold **Prompt:** label. Distinguish prose, prompts, and executable commands. |
| Tool names and commands become a wall of code | Group name, available logo, purpose, and official link. Put installation beside its tool/project. Do not invent one-click installation or imply all tools are required. |
| Repository links assume knowledge of terminals, WSL, and compatibility | Briefly explain relevant systems, execution locations, and what information to provide when asking for help. Necessary setup guidance is not defensive prose; do not promise unverified compatibility. |
| Diagrams become illegible or detached from introductions | Inspect at actual reading width, adjust size and placement, and preserve approved visuals. |
| Homepage and track pages duplicate full paper lists | Follow agreed navigation, merge repeated descriptions, and retain unique links. |

## Example review assignment

Supply actual artifacts, applicable requirements, and permitted pages rather than only the author's completion summary:

> Review the specified guide from a first-time student's perspective. Check resource purpose, distinctions between prose, prompts, code, and competition requirements, link destinations, image readability, and the relationship between descriptions and visuals. Preserve approved material. Report evidence-backed findings with location, consequence, and correction. Inspect accessible links and pages; identify uninspected portions. Do not edit or publish.

Repeated components may first be developed and reviewed as one complete example before expansion; each page's unique resources and content still need checking. Inspect images, links, and attachments in the target platform. Do not repeatedly verify material already supported by clear evidence. The editor handles findings instead of turning fixable defects into another assignment for the user.
