# 知识库：资源用途与主动审阅

2026 年 10 月的无界杯新生学习指南暴露了这些问题。它们用于校准判断，不要求所有文档采用比赛指南的结构。

| 失败案例 | 修改方向与检查依据 |
|---|---|
| 课程卡片有封面和介绍，却没有明确的视频链接 | 标题或附近文字提供可点击链接；平台支持时图片也链接同一视频。图片链接不能替代文字入口。 |
| 每项资源都写“先看……再做……最后保存……” | 简短介绍实际内容，必要时解释知识联系。引导帮助理解，硬指导凭空安排动作；真实安装依赖和用户要求的课程顺序仍保留。 |
| 为避免解释，标题下只剩图片或重复标题 | 用简短具体的介绍承接图片或链接；标题已经足够清楚时不强加一句套话。 |
| 每张卡片都有“论文原图 · Figure 1 · PDF 第 2 页” | 保留来源，图注说明必要的图意。页码用于引文定位时有用；仅标记素材制作位置时可省。分卷 PDF 的页码有导航作用，不应一并删掉。 |
| 把 CUHK 示例当成数据入口，未说明参考价值 | 说明模型结构、训练方法或数据处理的参考价值，以及与当前任务有关的差异。数据、方法、环境、Agent 框架和比赛包不能因主题相关就互相替换。 |
| 用户要尝试官方 MineDojo／LIBERO，却被引向比赛工作包 | 保持官方实践入口；比赛流程只在授权的相关部分介绍，不能擅自混入。 |
| 大段提示词夹在正文里 | 独立呈现，加粗 **Prompt：** 标签；区分介绍、可复制提示词和可执行命令。 |
| 工具名、安装命令、代码框堆成一页 | 工具名称、可用 logo、用途和官方入口成组排列；安装内容放在对应工具或项目旁。不发明“一键安装”，不暗示必须安装全部工具。 |
| 只给仓库链接，默认新生知道终端、WSL 和兼容性 | 简述相关系统要求、运行位置及求助所需信息。必要环境说明不是防御性废话；未经核实不许诺任意电脑都能运行。 |
| 图片缩小后文字不清，简介远离配图 | 按实际阅读宽度调整尺寸和位置，保留用户认可的图。源文件里有图片，不代表发布页面可读。 |
| 首页与方向页重复列全部论文 | 按选定导航结构归拢，合并重复介绍，保留独有资源链接。 |

## 审阅任务示例

给审阅者实际产物、适用的用户要求和允许访问的页面，不只给作者的完成总结：

> 请从第一次打开页面的新生视角审阅指定学习指南。判断每项资源的用途是否清楚，正文、提示词、代码和比赛要求是否可区分，链接是否对应，图片是否可读，介绍与图片是否自然衔接。保留用户认可的内容。只报告有证据的问题，给出位置、影响和建议；能访问的链接和页面请实际检查，未检查的部分注明。请勿编辑或发布。

重复组件可以先做一个完整样例，审阅后扩展；扩展后仍需核对每页独有的资源和内容。图片、链接和附件在目标平台检查；已有明确有效证据的内容无需反复验证。报告交给执行者处理，不把能自行修正的问题再变成用户的作业。
