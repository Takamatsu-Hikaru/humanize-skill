# 校准样例：AI 入门指南与赛事方案

来自 2026-10-11 至 12 日的实际编辑讨论。以下区分用户认可的文字、被否定的写法和后来形成的处理方式。学习句子之间的关系，不要把这几篇文章的结构推广成所有文章的固定模板。

## 1. 基础知识：保留真正的论述

用户认可并要求保留的原文：

> 做研究可以自顶向下，但也要由浅入深的学习理解数学、ML/DL 和计算机，打好基础。一个推荐的学习心法是按需学习而非顺序学习，并灵活运用课程、blog 等多种学习资源。可以先学习到不影响理解的层次，也可以针对你的项目、论文方向系统补充相关知识。我们主要需要学习的基础知识是 Python、计算机、机器学习、深度学习与一些数学基础。

被否定的改写：

> 做研究可以从一个感兴趣的问题出发，在读论文、写代码和做实验的过程中补充知识；也可以通过课程，系统学习数学、机器学习和计算机。两种方式可以结合起来。课程适合建立整体认识，教材、技术博客和代码则能把某个具体问题讲得更深入。

第二段语法没有明显问题，但用“项目 / 课程”分类替代了作者关心的知识深度与学习顺序，还武断地给不同媒介分配了功能。好编辑首先保住原来的思路，不先追求句式圆滑。

## 2. 数学与模型：解释需要有对象

保留：数学部分提到条件概率、期望、梯度、KL 散度，在后面用语言模型、生成模型和强化学习展示它们怎样进入模型与训练目标。

删去的方向：每段再补“理解它们，就能理解前沿研究”“这些知识能帮助你建立认知”。

前者是具体联系，后者是抽象的学习收益。短衔接可以定调，没必要将所有模型名在总述、各节和小结里重复三遍。也不能为让联系显得整齐，暗示 VAE、Diffusion、Flow 都依赖完全相同的数学。

## 3. 第一个项目：让人看到想试的东西

被否定的方向：做完项目便有机会找到研究问题；初次介绍数据集就强调样本少、不能用于实际性能比较。

认可的开头：

> 如果你想玩玩 AI，看看它能做什么，可以从一个小项目开始。让模型认出手写数字，在自己拍的照片里框出人和车，或者让它调用工具帮你处理事情，都可以试试。

这里用具体结果建立兴趣。讲训练评测时仍可解释数据划分；初次试跑的段落不需要提前展开所有评测限制。不要由这个例子推导出“所有 caveat 都删掉”。

## 4. 论文页：把资源说清楚

| Before | 采用的处理 | 原因 |
|---|---|---|
| 已经有问题，再翻长清单 | 更多论文 | 不给访问资源预设资格或状态。 |
| 跟着有经验的人读一次 | 论文讲解；正文直接介绍李沐精读 | 说清具体内容和来源。 |
| 先挑一个方向，再选一篇看它怎样提出问题、怎样验证想法 | 删掉这层流程说明 | 已有筛选和论文介绍，不需要重复安排动作。 |
| 附有配图、简要介绍和论文链接 | 删除 | 读者在页面上已经看得到。 |
| 这里也在部分小卡中附上了相关链接，例如…… | “论文的配套讲解还有很多……比如 Transformer 的图解文章和带注释的代码实现。” | 例子紧跟前一句内容，不介绍本站如何组织链接。 |
| 49 张卡片 → 引言 → 重复推荐部分论文 | 引言 → 49 张卡片 → 讲解 → 更多论文 | 顺序本身承担说明功能。 |

最后该页标题改为“论文选读”。保留所有 49 张卡片、图、筛选和详情。标题的改变是这个页面的选择，不能推导出所有“挑一篇”“试试看”都不自然。

## 5. 链接与来源

资源标题表达内容，例如“Attention、位置编码与生成模型推导”。来源使用“科学空间”及其 blog 链接。具体文章如“如何搭建一个科学的 Scaling Ladder”链接文章，作者 handle 另链接其 blog。

网站中按主题就近放链接；一个段落不反复链接同一个入口。公众号可能需要文末链接目录，但不能因为换媒介就丢掉原始网址。

## 6. 保留已经成立的呈现

首页的读者问题导航表、方向介绍的图示、术语速查的搜索，分别有明确用途。用户只要求术语速查与主站统一配色时，保留其正文和功能。不要在一次样式调整里顺手进行全站文案改造。

用户称赞过的首页会使用“如果你……”；这与否定论文正文里反复分支并不矛盾。重点是整页功能和密度，不是某个词是否出现。

## 7. 赛事方案：陈述内容与安排

2026-10-12，用户要求将供学长审阅的赛事方案改为正式、直接的陈述，并认可改后的版本。此前稿件误用了面向参赛新生的引导和招呼语气。这里的正式程度来自实际读者与用途，不是所有文章都要采用的语气。

| 原写法 | 采用的写法 | 改动的依据 |
|---|---|---|
| 面向哪些同学 | 参赛对象 | 标题直接标识信息类别，便于审阅和查找。 |
| 参加能收获什么 | 预期收获 | 陈述文档主题，无须模拟与读者问答。 |
| 官网承担什么 | 官网功能 | 用具体内容名称替代引导式问题。 |
| 先在群里了解比赛和登记队伍 | 报名与队伍登记 | 标题说明本节内容，具体流程放入正文。 |
| 群文件按这个顺序发布 | 资料发布安排 | 日期与发布顺序由表格表达，标题无需再次指挥阅读。 |
| 做点好玩的东西 | AI 应用体验 | 面向审阅者陈述参赛价值；正文用动作识别、开放世界探索与机械臂任务说明具体体验。 |
| 找到一起做事的人 | 交流合作与学长指导 | 保留用户明确要求的合作经历和向学长请教，不用亲切感代替信息。 |
| 尝试研究一个具体问题 | 科研实践经历 | 正文明确方法比较、对照实验、错误分析与研究发现汇报。 |
| 第一块……第二块…… | 赛事发布、资料与资源准备、专题讲座等阶段名称 | 具体阶段名承担结构功能，编号只用于定位。 |

被否定的段落：

> 先让同学进得来、看得懂、能报名。总群、公告、四份说明文件和登记表一起准备，宣传链接统一指向进群与报名入口。

采用的段落：

> AI 社将于 10 月 13 日统一发布赛事公告、赛事总说明、三份赛题 PDF 和队伍登记表，并建立比赛总群。宣传文案、海报及易拉宝统一提供进群与报名入口。

改后明确了行动主体、日期、材料及宣传入口。原稿把目标写成口号，又用“一起准备”模糊处理具体安排。问题不只在口语词，而在于用讲解姿态代替了可供判断的内容。

“把读者当傻子”的感受常来自不必要的指导密度：反复告诉读者先看哪里、再做什么，默认他们无法自行理解已经清楚列出的信息。适当的教程步骤依然有用；本例的审阅者需要评估方案，不需要被带着阅读方案。

“怎么、先、后、一个、两个”本身都自然。“测评后约 10 天安排答辩”“三份赛题 PDF”提供了真实关系与数量，应保留。应去掉的是无依据的步骤、泛泛的鼓励和填充性的数数。标题改成名词后，正文仍须同步校准，否则只换了表面。

## 8. 写作页：从主线到两遍检查

这轮讨论里，用户反复纠正的不是个别词语，而是文章为什么突然聊到这里。写作页如果一上来就说“可以先用几句话写出……”或摆出几个工具，读者还不知道为什么开始讨论写作，也不知道这些建议为谁服务。

用户确认的顺序是：从研究怎样变成文章引出写作；说明主线及摘要、引言、问题设定、方法等部分的作用；再讨论写稿改稿时怎样追问“为什么在这里说这件事、到底传达什么”；随后谈 defensive、过度解释、自我弱化与 AI 味；最后接相关写作资料、工具和 rebuttal。Introduction 从背景、问题和动机引出 proposal，setup 形式化问题，method 解释做法，是这篇文章里的具体例子，不是给所有文章强加论文结构。

**内容检查**看这些 part 是否共同服务于“怎样把研究讲清楚”，有没有断开的章节或工具抢在问题前面，核心解释是否被各种提醒挤掉。**表达检查**看铺垫和承接是否自然，建议有没有变成居高临下的指令，有没有凭空预设批评；也看删减是否把真正的经验写成了干巴巴的常识。

同样是解释代码，“文件太多也没关系，先列清单，再逐项验收”没有说明怎么理解实现；“对照论文里的架构和设计，跟着数据在程序里走一遍，再看训练和推理分别怎样完成”给出了实际的理解线索。AI 可以结合论文和仓库带着读者理解，这个具体作用值得保留。不要又在段末安排没有必要的作业。

## 自查情境

新版本技能有实质改动时，可任选相关情境试用，无须每次完整跑一套。

1. 输入资源介绍“这是系统建立领域认知的重要入口，先读一篇再保存记录”。看成稿能否介绍真实资源，避免换一套空话；信息不足时不捏造课程内容。
2. 用户要求保留自己写的基础引言、只调整下面链接。看是否真的保留引言，而不是把它抹平。
3. 公众号稿含一张复杂论文图和八个外链。看是否安排可读的裁切/分图和清楚的链接去向，同时保留原图来源；不能用装饰画取代技术信息。
4. 同一赛事材料分别用于学长审阅和新生招募。审阅稿应直接陈述对象、资源、安排与责任；招募稿可保留适合受众的邀请语气。两稿均保留具体事实，不用一套语气覆盖两种用途。
5. 写作页含开篇、章节介绍、改稿经验、AI 工具和 rebuttal 资料。检查每部分为什么出现、前后怎样相接、内容比例是否合适；不要只删除几个词就宣称完成。
6. 用户要求“把 humanize skill 做成英文版并补充两遍检查”。应修改技能及对应参考文件；不能把最近讨论过的网站翻译一遍当成完成。
