# 配图、页面与公众号

## 先看内容怎样展开

沿用作者已经确定的文章顺序。找出读者真正需要看见的对象：模型输出、界面位置、结构关系、变化过程、数据比较或现场场景。图的数量取决于材料；没有必要每个标题下一张图。

有时一张项目结果截图比一段解释更清楚，有时原理需要文字推导。配图可以提供气氛，但应与文章主题和视觉语言有关。不要默认采用发光大脑、机器人头像、紫蓝渐变、堆叠卡片或“从零到精通”式封面。

## 选择图的来源和形式

| 内容 | 通常合适的图 | 放置和处理 |
|---|---|---|
| MNIST、YOLO 等项目 | 真实预测结果、用户自己的图片或官方演示 | 放在介绍结果之后；保留能看懂类别和效果的区域。 |
| 论文和模型原理 | 原论文图、自己绘制的准确示意图 | 与相关机制放在一起；给出来源。重绘保持关系、符号和尺度含义准确。 |
| 工具使用 | 实际界面截图或短录屏 | 紧接对应操作；显示有关区域，不把一整块桌面缩成小图。 |
| 课程与视频 | 官方页面截图、视频封面或用户提供的 B 站截图 | 资源名称与链接保持文字可访问，不只藏在图片里。 |
| 概念关系或对比 | 简图、表格、并排结果 | 选读者能直接比较的排列；复杂关系避免强行画成线性箭头。 |
| 封面与编辑插画 | 合适照片或原创插画 | 建立文章气质，避免在图上重复整个标题和引言。 |

先检查已有图和用户提供的素材，避免重复生成。缺少关键截图时记录具体需要哪个画面，并完成不依赖它的部分；不要伪造界面、实验结果或引用。对外部图片记录来源和已知使用条件，图片来源与链接说明放在图注或素材记录中，不写成正文里的免责长段。

需要原创位图或编辑现有图片时使用当前可用的 imagegen 工具及适用技能。精确结构图和数据图使用能保证标签、连线和数值正确的绘图方法。不要因为插画工具擅长某种风格，就让所有内容都变成同一种画法。

生成图片前明确画什么、出现在哪段、画幅和与现有版式的关系。生成后实际查看图片，再决定使用。长文有多张图时简要记录位置、素材来源/生成方式、文件名和图注；不必为单张插图建立繁复的审批流程。

## 页面层次

多页知识库或课程资源集合同时参考 [知识库审阅](knowledge-base-review.md)。按主技能的主动审阅要求检查实际页面：文字入口、图片可读性、提示词标识与资源用途应一起成立，不能只检查文案或只看截图。发现重复组件的问题后，检查授权范围内的其他实例。

标题表达主题；引言建立缘由；小标题区分内容。正文用连贯段落。只有确实并列、比较或逐步执行的信息才用列表和表格。

通过段间距、标题层级、图片宽度和留白形成节奏。强调只给需要被扫读到的信息，不把每段第一句都加粗。不要把一篇文章拆成几十个只容纳两句话的卡片。

同一品牌先复用既有色彩、字体和图形语言。AI 入门指南的参考颜色为暖纸色 #f4f1ea、正文 #20211e、链接绿 #24583e、强调色 #98432e；这些是这个项目的偏好，不是所有文章的固定皮肤。

## 公众号：从网页改成一篇能读下去的文章

网站里的导航、筛选、弹窗和折叠内容需要重新安排。例如网站有 49 张论文卡片，公众号可以介绍本期选定的几篇并链接完整目录；选取范围需要符合用户要求，不能擅自把整套资料删成几张图。

公众号版本需要继续保留原始 Markdown 或其他可编辑正文。文章里有长代码、横向表格、公式或复杂图时，先检查手机上是否能读；拆表、分图和短代码示例通常比缩小字号更实用。关键资料不能只存在于一张不可复制的长截图中。

### 排版起点

没有指定样式时采用简单、单栏、左对齐的文章样式。正文约 16px、行高约 1.8、左右留白约 20px，可作为起点；按字体和实际预览调整，不把这些值当平台规格。

公众号标题字段与正文首标题避免无意重复。二级标题明确分节，三级标题仅在内容需要时使用。图注较小但清晰，链接有可识别的颜色，强调色保持节制。正文可以白底，品牌色用于标题或少量强调，不必照搬网站整个背景。

[wechat-base.css](../assets/wechat-base.css) 是无依赖的样式起点，可用于预览或交给支持自定义 CSS 的渲染器。根容器使用 class="humanize-article"。导出到公众号时将需要的 CSS 内联；单独引入样式表的浏览器预览不能等同于可粘贴到编辑器的成品。

### 转换与工具

已有项目转换器时优先复用。否则根据可用工具选择 doocs/md、baoyu 的 Markdown 转 HTML，或生成简单的内联样式 HTML。具体工具入口见 [github-references.md](github-references.md)。仅需文案时不安装排版工具；仅需排版时不调用发布插件。

外链与图片在公众号编辑器里的实际表现需要验证。用户需要文末引用或当前编辑器不能按预期使用外链时，保留正文资源名称，将网址按出现顺序整理到文末；去重并维持对应关系。不要把几十条裸链接散落在段落间，也不要未经核实声称任意外链都能点击。

图片、公式、Mermaid 等若依赖脚本或浏览器特性，转换为平台可呈现的形式；技术标签和数值需要可读。单页里的绝对定位、多栏布局、外部字体等不应成为文章能否正常阅读的前提。转换器输出图片占位符时，完成实际图片映射后才称为完整稿。

### 查看实际结果

在手机阅读宽度下查看开头、一个内容较密的中段、图片和文末资源。检查文字是否挤成一块、图中文字是否可读、链接是否成堆、表格是否溢出，以及图片和正文是否真的讲同一件事。

若有已授权的公众号编辑器操作，再检查粘贴或导入后的样式、图片和链接。只做了本地预览，就准确交付本地预览，不说已经发布或已在公众号验证。

交付以可编辑正文、排版 HTML、实际图片为主；多图项目附简短素材来源记录。没有配图需求就不建立空图片目录，不用给每篇文章附一份冗长的排版报告。
